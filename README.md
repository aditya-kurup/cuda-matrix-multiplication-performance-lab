# CUDA Matrix Multiplication Performance Lab

An FP32, row-major matrix multiplication experiment with a one-output-per-thread CUDA kernel and a shared-memory tiled kernel. The focus is correctness and reproducible measurements on an NVIDIA GPU. The [static demo](docs/index.html) visualizes a small teaching example and reads measured JSON after a GPU run; it does not execute CUDA in the browser.

This repository can be edited on an M4 MacBook Air. CUDA compilation, GPU tests, and measurements require a Linux runtime with an NVIDIA GPU, such as Google Colab. No measured results are included until that run happens.

## Project map

| Path | Purpose |
| --- | --- |
| `src/main.cu` | CUDA kernels, GPU correctness suite, benchmark runner, JSON writer |
| `include/reference.hpp` | Deterministic inputs, double-accumulation CPU reference, error comparison |
| `tests/reference_test.cpp` | Host-only reference and tolerance checks, runnable on macOS |

| `notebooks/colab.ipynb` | GPU check, clone, build, test, benchmark, results, download |
| `docs/` | Static GitHub Pages demo; `docs/results/benchmark.json` is generated by a real run |

## Run in Google Colab

1. Push this repository to a public GitHub repository. In Colab, open `notebooks/colab.ipynb` from GitHub (File → Open notebook → GitHub, then enter the repository URL), or upload the notebook.
2. Select **Runtime → Change runtime type → GPU**. Run the notebook from top to bottom. Enter `https://github.com/OWNER/REPO` in its first code cell. The notebook checks `nvidia-smi`, `nvcc`, and CMake, clones or updates the repository, and prints the detected GPU and toolkit version.
3. The next cells build the executable, run the deterministic correctness suite, run the short benchmark sweep, display measured values, and download `benchmark.json`. A failure stops the notebook; no benchmark file is written after a correctness failure.
4. Add the downloaded file to this repository at `docs/results/benchmark.json`, commit it, and push. It is intentionally absent from the starter project. GitHub Pages will then display the real run.

After a Colab reset, run all cells again. If the runtime has a GPU but lacks `nvcc`, select another GPU runtime or install a compatible CUDA toolkit following the current Colab/NVIDIA guidance, then rerun the build. The notebook reports the missing tool instead of skipping work. It does not assume a GPU model or toolkit version.

### Direct Linux commands

Run these from the repository root on a CUDA-capable Linux machine:

```bash
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build -j2
ctest --test-dir build --output-on-failure
./build/matmul_lab --test
./build/matmul_lab --benchmark --output docs/results/benchmark.json
```

`ctest` and `--test` run the same GPU correctness suite; one is sufficient. With no flags, the executable runs the correctness suite followed by the short benchmark. The optional longer sweep is:

```bash
./build/matmul_lab --benchmark --expanded --output docs/results/benchmark.json
```

`--trials N` changes the default nine measured trials. The short sweep is 64×64×64, 128×128×128, 256×256×256, 127×65×191, and 256×128×384, written as M×K×N. The expanded sweep adds 512×512×512, 768×512×256, and 511×257×769.

## Correctness and indexing

For `A` of M×K and `B` of K×N, `C[row,col] = sum(A[row,inner] * B[inner,col])`. Row-major offsets are `A[row*K + inner]`, `B[inner*N + col]`, and `C[row*N + col]`. The naive grid maps one thread to each `(row,col)`. The tiled grid maps one 16×16 block to a C tile. Threads load A and B tile elements cooperatively, zero-fill any input outside M, K, or N, synchronize before using the shared tiles, and synchronize again before overwriting them. Only valid output coordinates are stored.

Inputs are deterministic FP32 values made by dividing small integers by 9, so typical products exercise rounding. The CPU reference accumulates products in `double` and converts the final value to FP32. Both kernels must pass **for every element**: `abs(actual - reference) <= 1e-3 + 1e-4 * abs(reference)`. Non-finite outputs fail. The program reports maximum absolute error and maximum relative error (relative denominator `max(abs(reference), 1e-6)`); the reported relative maximum can be large near a zero reference even when the mixed tolerance passes. Small, rectangular, exact-tile, and awkward edge cases are covered separately from benchmark shapes. Benchmark outputs are also checked before timing.

## Measurement method

The executable uses CUDA events in the default stream. Each measured action gets three warmups, then nine trials by default. It records each trial, median, minimum, and maximum. Kernel events surround only the kernel launch; they exclude host-to-device copies, device-to-host validation, CPU reference work, allocation, and most host launch overhead. Host-to-device transfer timing is reported separately using pinned host buffers and two asynchronous copies, A then B. Event timing of very short kernels can be noisy, so compare the spread, not only the median. The input data, sweep, tile size, block dimensions, warmups, and trial count are fixed or recorded.

GFLOP/s uses `2*M*K*N / (median_ms * 1e6)`. The tiled/naive ratio uses their **measured** median times for the same shape. It is not a claim that tiling always wins. Launch and timing overhead matter most for small work; reuse has more opportunity to matter as K and output size grow. These are explanations of plausible effects, not profiler findings. Timings from different Colab GPUs or sessions should not be treated as controlled hardware comparisons.

### JSON format (`schema_version: 1`)

The generated `docs/results/benchmark.json` contains:

| Field | Meaning |
| --- | --- |
| `generated_at_utc` | UTC timestamp of the run |
| `environment` | GPU name, compute capability, CUDA runtime and driver versions, CUDA header version (integer encoding, e.g. 12040 means 12.4), and `nvcc` compiler major.minor |
| `methodology` | Warmup count, trial count, short/expanded sweep, timing description |
| `results[]` | One object per shape with `m`, `k`, `n`, transfer timing, and kernel results |
| `results[].h2d` | `median_ms`, `min_ms`, `max_ms`, and `trials_ms` for both input copies together |
| `results[].kernels[]` | `name`, `block` `[16,16]`, `tile_size` (0 naive, 16 tiled), correctness, timing, GFLOP/s, and speedup versus naive |
| `correctness` | `passed`, `max_absolute_error`, `max_relative_error` |

The raw trial arrays are included so medians and spread can be rechecked. Each JSON is one GPU run, not an average across sessions.

### Optional Nsight Compute

In a CUDA-capable environment, check `command -v ncu`. If available, try:

```bash
ncu --set basic --kernel-name tiled_kernel ./build/matmul_lab --benchmark --trials 1 --output /tmp/profile-run.json
```

Colab may restrict performance counters or profiling permissions. If `ncu` is absent or access is denied, skip this optional step; the project is complete without it. Do not publish large `.ncu-rep` files. A profiler result should be described only after it actually runs, with the metric and GPU named.

Wait for GitHub's deployment, and visit `https://OWNER.github.io/REPO/`. After the Colab run, commit and push `docs/results/benchmark.json`; Pages will redeploy with the measured results. Source links on the public site resolve to the repository's `main` branch.

## Interview walkthrough

The output grid assigns one `(row,col)` to each thread; the naive kernel loops over K using row-major offsets. In the tiled kernel, a 16×16 block loads two shared-memory tiles. Barriers protect both the read of a completed tile and the overwrite for the next K segment. Bounds checks zero-fill partial tiles and guard output stores, so rectangular sizes and nonmultiples of 16 are safe. Deterministic cases compare every GPU output against a higher-precision CPU reference using a stated FP32 tolerance. CUDA events measure repeated kernel executions separately from H2D transfers, and the JSON preserves all trials. A speedup ratio establishes only the relative kernel time for a recorded shape on a recorded GPU in that run; it does not establish cache traffic, occupancy, or universal performance across hardware.
